## Sessão e proteção da API

- Senhas: scrypt assíncrono (`N=32768`, `r=8`, `p=3`), sal aleatório de 16 bytes e chave de 64 bytes. A comparação usa `timingSafeEqual`.
- Conta inexistente, inativa, senha incorreta ou credenciais inválidas recebem a mesma mensagem e derivação de senha de custo equivalente. Hashes e atributos internos não aparecem nas respostas.
- Token opaco de 32 bytes aleatórios; só seu SHA-256 fica no repositório de sessões. O token é entregue por cookie `labrary_session`, `HttpOnly`, `SameSite=Strict`, `Path=/api`, com `Secure` em produção. Não há token no localStorage.
- Expiração absoluta de 8 horas. Novo login rotaciona a sessão apresentada; logout apaga a sessão no servidor, limpa o cookie e aceita repetição. Reiniciar o processo invalida todas as sessões.
- `GET /auth/me` restaura a sessão. A interface volta ao login ao receber `401` e verifica a sessão ao retornar para uma aba. Falha de logout é informada sem fingir que a sessão foi revogada.
- Todas as mutações, inclusive login/logout, exigem `X-CSRF-Protection: 1`. Se houver `Origin`, ele precisa ser igual a `APP_ORIGIN`; `Sec-Fetch-Site: cross-site` também é rejeitado. Não há CORS habilitado. O frontend e a API devem ser servidos na mesma origem, por proxy.
- Limite de 20 tentativas de login por IP em 15 minutos, incluindo tentativas válidas, com `429` e `Retry-After`. O servidor não confia em `X-Forwarded-For` enviado pelo cliente.
- API com `Cache-Control: no-store`. Uma sessão é validada e as permissões são calculadas a cada requisição; nenhum papel, grupo ou turma é aceito de cabeçalhos do cliente.
- Ausência de sessão: `401`. Operação de papel indevido: `403`. Projeto existente fora do escopo e projeto inexistente: mesmo `404`, inclusive para materiais. Filtros só reduzem o conjunto autorizado.

Referências de implementação: [sessões OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [CSRF OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) e [scrypt do Node.js](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback).

## Contas provisionadas fora do seed

Defina `AUTH_DEMO=false` e `AUTH_USERS_FILE` com um caminho absoluto de um JSON privado. O arquivo é validado e carregado na inicialização. Alterações exigem reiniciar a API; isso também invalida as sessões antigas. Nunca coloque esse arquivo no Git (o diretório `.auth/` está ignorado).

Gere um hash sem passar a senha como argumento do processo ou registrá-la no histórico do Bash:

```sh
read -rs -p 'Senha (mínimo 12 caracteres): ' LABRARY_PASSWORD
printf '%s' "$LABRARY_PASSWORD" | pnpm --silent auth:hash
unset LABRARY_PASSWORD
```

Use o hash retornado no campo `passwordHash` do seguinte formato; o marcador precisa ser substituído antes de iniciar:

```json
{
  "users": [
    { "id": 1, "fullName": "Professor responsável", "email": "professor@example.edu", "passwordHash": "SUBSTITUA_PELO_HASH_SCRYPT", "role": "PROFESSOR", "active": true }
  ],
  "classes": [
    { "id": 1, "name": "Laboratório de Sistemas Digitais", "academicYear": 2026, "professorId": 1 }
  ],
  "groups": [
    { "id": 1, "classId": 1, "name": "Grupo 01", "memberIds": [] },
    { "id": 2, "classId": 1, "name": "Grupo 02", "memberIds": [] },
    { "id": 3, "classId": 1, "name": "Grupo 03", "memberIds": [] }
  ],
  "assignments": []
}
```

IDs e e-mails devem ser únicos. Classes precisam referenciar professores, membros precisam ser alunos e atribuições precisam referenciar avaliadores. `memberIds` representa os vínculos atuais; `assignments` usa `{ "projectId": 1, "evaluatorId": 2 }`. Os IDs devem corresponder aos projetos do repositório.

**Limite desta entrega:** projetos, metadados, sessões e contador de tentativas ficam em memória por processo. Os projetos voltam ao seed e as sessões são invalidadas ao reiniciar. Contas provisionadas persistem no JSON de origem. PostgreSQL/Prisma permanece modelado, ainda sem adapter conectado; não há upload de bytes. Esse modo serve ao incremento local da Sprint 2 e não oferece armazenamento durável de projetos nem suporte a múltiplas instâncias. Para implantação real, conectar os repositórios ao banco, compartilhar sessões/limites e servir frontend/API na mesma origem HTTPS. A criação de usuários e o envio de arquivos não são apresentados como funcionalidades prontas.

```sh

pnpm exec playwright install --with-deps chromium

Excluídos somente testes/helpers, entrada do servidor, CLI de hash, código Prisma gerado e bootstrap React; controllers, serviços, repositórios, componentes e cliente HTTP estão incluídos.
- `.github/workflows/ci.yml` executa build, testes com cobertura e navegador em pushes/PRs e armazena os relatórios. A execução remota do workflow depende de publicar as alterações.
